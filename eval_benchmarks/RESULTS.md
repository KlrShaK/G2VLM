# G2VLM on VSI-Bench & VSTI-Bench (random-200 subsets)

**Model:** `G2VLM-2B-MoT` (`models/G2VLM-2B-MoT`, 4.54 B params: Qwen2-VL LLM + Qwen2
ViT + DINOv2 geometry encoder).
**Harness:** `eval_benchmarks/` — frames sampled uniformly with decord
(`np.linspace(0, N-1, k)`, identical to lmms-eval), prompts built byte-identically
to each benchmark's `vsibench_doc_to_text` (verified: 0/400 mismatches), scored with
each benchmark's own metric code (`metrics.py`, copied verbatim).
**Subsets:** canonical `shuffle(seed=42).select(200)` — the VSI subset is byte-identical
to SpatialStack's `vsibench_random200` (ids verified to match). VSTI uses the same rule
on `Journey9ni/vstibench`.
**Hardware:** 1× NVIDIA A100 80 GB PCIe.

---

## ⚠️ Key finding: G2VLM cannot ingest many frames

G2VLM is a **few-view geometry model**, not a video-QA model. Empirically it generates
coherent text only at **≤ 8 frames**; at **16 frames it degrades** and at **32 frames it
collapses into repetitive gibberish** ("…from the new new new new observer…") — at *every*
resolution tested (224 / 336 / 448 / 768 px), so the failure is driven by frame **count**,
not token budget. Even when coherent, it answers in its native depth-estimation style
(e.g. *"the printer is ~2.0 meters from the observer"*) rather than emitting an option
letter or a bare number, so QA-format accuracy is low regardless.

Consequence:
- **32-frame runs** (benchmark-faithful protocol) → outputs are degenerate → scores ≈ 0.
  These document the protocol-level result honestly but reflect a *generation failure*,
  not spatial ability.
- **8-frame runs** (coherent regime) → the model produces real answers; VSI numbers are
  meaningful but **not directly comparable** to the 32-frame baselines. VSTI's questions
  reference "frame X of 32", so at 8 frames those questions are **semantically broken** —
  the VSTI-8f number is a generation-sanity check, not a valid benchmark score.
